# SignalWatch API Reference

Base URL (local): `http://localhost:8000`
Interactive docs (auto-generated by FastAPI): `/docs` (Swagger) and `/redoc`.

All responses are JSON. Errors return `{"detail": "<message>"}` with an appropriate HTTP status code.

---

## Watchlist

### `POST /watchlist`
Add a symbol to the watchlist.

**Body**
```json
{ "symbol": "RELIANCE" }
```

**Responses**
- `201 Created` → the created watchlist item
- `409 Conflict` → symbol already in the watchlist
- `422 Unprocessable Entity` → empty/invalid symbol

### `GET /watchlist`
Returns all watchlist items, oldest-added first.

### `DELETE /watchlist/{symbol}`
Removes a symbol.
- `200 OK` → `{"detail": "SYMBOL removed"}`
- `404 Not Found` → symbol wasn't in the watchlist

## Market

### `GET /market`
Returns live quotes for the entire watchlist. Empty watchlist → `[]` (not an error).

### `GET /market?symbol=RELIANCE`
Returns a single live quote (does not require the symbol to be on the watchlist).

Each quote includes `error` (non-null if the provider failed for that symbol), `freshness` (`live` | `cached` | `market_closed`), and `is_stale` (derived from `freshness`, kept for backwards compatibility). A failing symbol never breaks the rest of the response.

---

## Snapshot

### `POST /snapshot`
Persists a snapshot of current market data for the given symbols (or the whole watchlist if `symbols` is omitted), then immediately recomputes change events for those symbols.

**Body**
```json
{ "symbols": ["RELIANCE", "TCS"] }
```
or `{}` to snapshot everything.

Returns the list of snapshots that were successfully recorded (symbols with a fetch error are skipped, not failed).

## Changes (Attention Feed)

### `GET /changes`
### `GET /changes?unseen_only=true`
Returns change events sorted by score (descending), then recency. Each event includes:
- `score` (0–100)
- `label` (`Quiet` | `Worth Checking` | `Important`)
- `reasons` — human-readable, deterministic explanations
- `price_then` / `price_now` / `percent_change`

### `POST /mark-seen`
Marks change event(s) as seen so they stop appearing as "new" in the feed.

**Body** (send exactly one of these)
```json
{ "change_event_id": 42 }
{ "symbol": "RELIANCE" }
{ "mark_all": true }
```

## Insights

### `GET /mood`
Rolls up the watchlist's most recent change event per symbol into a single Market Mood.

```json
{
  "mood": "Watchful",
  "score": 34,
  "icon": "🧐",
  "color": "blue",
  "important_count": 0,
  "worth_checking_count": 1,
  "explanation": "1 stock worth a quick look."
}
```

`mood` thresholds are driven by the highest score currently on the watchlist: `0–20` Calm, `21–40` Watchful, `41–70` Active, `70+` Volatile.

### `GET /replay`
Returns Morning / Afternoon / Now prices for every watchlist symbol, bucketed from the `snapshots` table (IST day-parts). In Demo Mode, returns a deterministic synthetic replay instead, since a fresh demo session won't have hours of real snapshot history yet.

```json
{
  "stages": [
    { "label": "Morning", "prices": [{ "symbol": "RELIANCE", "price": 2931.10 }] },
    { "label": "Afternoon", "prices": [{ "symbol": "RELIANCE", "price": 2945.80 }] },
    { "label": "Now", "prices": [{ "symbol": "RELIANCE", "price": 2950.50 }] }
  ]
}
```

A symbol with no snapshot yet in a given bucket returns `"price": null` for that stage rather than guessing.

## Edge cases handled by the API

| Situation | Behavior |
|---|---|
| Invalid/delisted symbol | Quote returned with `error` set, `price: null`; never a 500 |
| Duplicate watchlist add | `409 Conflict` with a clear message |
| Market data provider timeout | Caught, quote marked `is_stale` + `error`, cached briefly to avoid retry storms |
| Market closed | `is_stale: true` on quotes so the frontend can show "Last close" |
| Empty watchlist | `GET /market` and `GET /changes` return `[]`, not an error |
| First-ever snapshot for a symbol | No change event is generated (nothing to compare against yet) |
| Removing a symbol mid-session | Historical snapshots/change events are kept for audit; only the watchlist entry is deleted |
| No real snapshot history yet for Daily Replay | Demo Mode serves a deterministic synthetic replay; live mode returns `null` prices for buckets with no snapshot rather than guessing |
